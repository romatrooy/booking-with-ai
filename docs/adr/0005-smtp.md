# ADR 0005. Письма гостю через SMTP

- **Статус:** принято.
- **Дата:** после `ADR-0004`.

## Контекст

Раньше (PDR-0001, раздел «Не делаем») сервис сознательно не
отправлял писем гостю: настройка почтового сервиса и его сопроводение
вынесены за рамки учебного проекта. Практика показала, что гость
хочет подтверждение, что его бронь дошла, и явное уведомление, если
бронь отменил администратор. Это даёт сервису законченный
пользовательский сценарий без необходимости регистрации или личного
кабинета.

## Решение

Письма отправляются гостю через **SMTP** с помощью `nodemailer`.
Никаких внешних SaaS — администратор сервиса сам выбирает провайдера.
Шаблон для Gmail приводится в `.env.example` и в README.

### Когда отправляем

- **После `POST /api/bookings`** (успех). Тема: «Запись на встречу
  «{activity_name}» подтверждена». Получатель — `booking.guest_email`.
- **После отмены** — гостевой `POST /api/bookings/{id}/cancel`
  и админский `POST /api/admin/bookings/{id}/cancel`. Тема:
  «Бронь на встречу «{activity_name}» отменена».

Администратору письма не отправляются. Это осознанное
упрощение: в `README.md` описано, как читать список всех броней
через `GET /api/admin/bookings`. Если потребуется отдельная
копия организатору — отдельная фича.

### Поведение mailer

Если ни одна из `SMTP_*` не задана, `mailer` — **no-op** (`async
ответствует undefined`, никаких побочных эффектов). Это нужно, чтобы:

- dev-режим без сконфигурированной почты продолжал работать;
- e2e-тесты и CI не падали из-за отсутствия SMTP;
- одна переменная окружения, забытая по ошибке, не ломала
  процесс, а давала понятную ошибку при старте (`SMTP: заданы
не все переменные. Не хватает: ...`).

### Ошибка отправки

Ошибка SMTP **не ломает ответ API**. Бронь уже в БД, ответ 201/200
клиенту уже ушёл; письмо — побочный эффект, его потеря
логируется с именем получателя, темой и ошибкой. Гость уже
записан, отмена уже состоялась — основная операция завершена.

Альтернатива (откатывать транзакцию при ошибке почты) не выбрана:
это значит, что гостю, у которого SMTP-сервер лежит, нельзя
бронировать вообще. Это жёстче, чем должно быть для побочного
эффекта.

### Реализация

| Файл                               | Что делает                                                                                                                                         |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `server/src/mailer.ts`             | `buildMailer(config)` → `Mailer` с `sendBookingCreated`, `sendBookingCancelled`, `isEnabled`. Шаблоны — литералы в коде, plain + HTML, на русском. |
| `server/src/config.ts`             | Чтение `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM`. Валидация «все или ничего».                                            |
| `server/src/app.ts`                | `app.decorate("mailer", buildMailer(config.smtp))`. Предупреждение в лог, если `!isEnabled()`.                                                     |
| `server/src/routes/bookings.ts`    | `void fastify.mailer.sendBookingCreated(...)` после `insertBooking`; `sendBookingCancelled(...)` после успешного `cancelBooking`.                  |
| `server/src/routes/admin.ts`       | То же для `POST /api/admin/bookings/{id}/cancel`.                                                                                                  |
| `server/tests/unit/mailer.test.ts` | Unit: no-op при `null`, `isEnabled()` при наличии конфига.                                                                                         |

### Переменные окружения

```
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=your-name@gmail.com
SMTP_PASSWORD=abcdefghijklmnop
SMTP_FROM=your-name@gmail.com
```

`SMTP_PORT=465` тоже работает (тогда nodemailer включает SSL вместо
STARTTLS). Default — `587`. Для Яндекса, Mail.ru и других
провайдеров — поменять `SMTP_HOST`, остальное то же.

## Последствия

**Становится проще**

- Гость сразу получает письмо — нет расхождения между «записался»
  в UI и «записался» в БД.
- Тот же код обслуживает и гостевую отмену, и админскую.
- Если SMTP не сконфигурирован, сервис всё равно работает —
  ничего не падает.

**Становится сложнее**

- Зависимость `nodemailer@6.x`. С такими же `bcryptjs`, она
  вторая зависимость за пределами стандартной цепочки Fastify.
  Это нарушает «не добавлять зависимости без явной
  необходимости» (`AGENTS.md` §10). Решение осознанное и
  зафиксировано здесь.
- Хранение пароля приложения в env. Пароль приложения Google
  не равен основному паролю аккаунта, но всё же даёт доступ
  к почте. Переменные окружения — компромисс для учебного
  проекта; в проде стоит держать токены в секрет-менеджере.
- Для тестов требуется либо мок-сервер SMTP, либо реальный
  Gmail. Здесь — только unit-тесты на сборку шаблона и поведение
  no-op. Интеграционная проверка отправки — ручной запуск
  с реальным конфигом.

## Альтернативы

- **Resend / SendGrid SDK.** Проще API, но это SaaS. SMTP —
  стандарт, и сервис не привязывается к одному провайдеру.
- **Очередь писем.** Сложно для учебного проекта. Если
  потребуется ретрай и надёжность — отдельная задача.
- **Сторонние шаблонизаторы (mjml, handlebars).** Лишняя
  зависимость ради простого письма.
- **Только plain-text.** Делаем plain + html (одна и та же
  функция почти без усилий), почтовые клиенты показывают что-то.

## Когда пересматривать

- Если потребуются вложения (ics-файл для календаря).
- Если потребуется несколько шаблонов (например, отдельный
  для организатора).
- Если `nodemailer` устареет и потребует миграции на API с
  существенными отличиями.
- Если потребуется очередь и ретраи (например, NDA или SLA).
